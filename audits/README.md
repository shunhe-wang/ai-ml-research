# Finalist audit matrix

No project is selected until each finalist has been attacked from all required angles. An audit may recommend rejection even when a project scores well in the preliminary screen.

| Audit | F1 sequential interference | F2 dynamic variants | F3 temporal rule versions |
| --- | --- | --- | --- |
| Literature search | Completed — major revision | Completed — major revision | Completed — reject as stated |
| Novelty verification | Completed — broad claim fails | Completed — broad claim fails | Completed — direct predecessor |
| Experimental design | Completed — conditional advance | Completed — hold/reject if no outer truth design | Completed — reject original; high-risk pivot |
| Statistical review | Completed — staged paired design | Completed — underidentified as proposed | Completed — decomposition not causal as proposed |
| Reproducibility | Completed — conditional | Completed — reject solo project | Completed — reject first project |
| Technical implementation | Completed — conditional | Completed — reject solo project | Completed — reject first project |
| Venue fit | Completed — major revision | Completed — major revision | Completed — reject pivot |
| Red-team criticism | Completed — major revision | Completed — conditional pilot only | Completed — retire |

## Required rejection tests

Each audit must attempt to show that:

1. the paper already exists;
2. the contribution is too small;
3. the evaluation cannot identify the claimed mechanism;
4. the likely finding is obvious;
5. the data or tasks are contaminated or invalid;
6. the methodology cannot support the conclusion;
7. the project is a benchmark without insight;
8. the result lacks a research audience;
9. implementation exceeds realistic resources; or
10. the output belongs in a blog post rather than a paper.

Final selection requires a written response to every surviving objection and explicit falsification criteria.
